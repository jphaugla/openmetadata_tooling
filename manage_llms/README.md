# Manage LLMs (NotebookLM Utilities)

This directory contains utility scripts to process and prepare the OpenMetadata and Collate documentation for ingestion into AI tools like Google's **NotebookLM**.

## Why does this exist?

NotebookLM is an excellent tool for chatting with your documentation, but it has a strict **500,000 word limit** per source document. The complete `llms-full.txt` files generated by our documentation sites frequently exceed this limit.

To solve this, `smart_split_llms.py` intelligently parses and splits the massive documentation text files into categorized, smaller chunks:
1. Connection Schemas & Options
2. Infrequent Connectors
3. API and Template References
4. Core Documentation

By separating the files this way, you can upload them to NotebookLM as multiple sources without hitting the size limits, allowing the AI to effectively index and search the entire corpus.

---

## Prerequisites

The splitting script writes directly to a directory (typically a synced Google Drive folder so NotebookLM can easily import them). You **must** set the `GOOGLE_DRIVE_LOCATION` environment variable to define where these files should be saved.

Example of setting this variable (you can add this to your hidden environment script, e.g., `~/.collate/setEnv.sh`):

```bash
export GOOGLE_DRIVE_LOCATION="~/Google Drive/My Drive/NotebookLM_Docs"
```

*Note: While the script only uses Python standard libraries (`os`, `sys`, `urllib`, `re`), macOS often has a complicated default Python environment. It is highly recommended to run this within a clean virtual environment:*

```bash
cd manage_llms/
python3 -m venv venv
source venv/bin/activate
```

---

## Usage

### 1. Run the Syncer

A wrapper script is provided to automatically download and split both the OpenMetadata and Collate documentation:

```bash
cd manage_llms/
./refresh_llms_to_drive.sh
```

### 2. Manual Execution

If you want to manually run the python script against a specific URL:

```bash
python3 smart_split_llms.py https://docs.open-metadata.org/llms-full.txt
```

The script will safely overwrite the files in your `GOOGLE_DRIVE_LOCATION` without deleting the file descriptors, preserving your NotebookLM source links if they are already connected!

---

## Automating with Cron

If you want to run this script automatically on a schedule (e.g., via `crontab` on macOS or Linux), be aware that cron jobs execute in an empty environment. You must define the `GOOGLE_DRIVE_LOCATION` directly within the crontab file so the script can find it.

Open your crontab (`crontab -e`) and add your variable at the top, followed by your scheduled task:

```bash
# Define your environment variable at the top of the crontab
GOOGLE_DRIVE_LOCATION="/path/to/your/Google Drive/My Drive/NotebookLM_Docs"

# Example: Run the refresh script every Monday at 8:00 AM
0 8 * * 1 /path/to/your/repo/manage_llms/refresh_llms_to_drive.sh > /tmp/llm_refresh.log 2>&1
```

*Note: The `refresh_llms_to_drive.sh` wrapper script is designed to automatically change into its own directory and activate its local `venv` (if one exists), making it safe to call from cron.*
